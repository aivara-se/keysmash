# Keysmash: systems

One page in the browser, built to static files. Nothing runs on a host.

## Architecture

GitHub Pages serves the files `bun run build` emits. The shell is one client-rendered SvelteKit page, prerendered twice: to `index.html`, and to `404.html`, which is what Pages answers for a path the app does not hold. A catch-all route renders the same screen, so no address opens a not-found page.

Behind the screen sit four parts. **The mark** reads the text against the word packs and colours each marked word; it holds no text of its own. **The store** keeps the packs, their emoji and the parent's pictures in IndexedDB, and its language in `localStorage`; it is the copy the app marks from after the first run. **Speech** names a letter: the device's own local voice when there is one, and otherwise committed clips played from `static/clips/`, generated by `scripts/make-clips.ts`. **The service worker** precaches the shell, the packs and the clips, so a first run with the network off still opens with words on it.

The boundary: the child's text lives in memory for the length of the session and is written nowhere. Nothing is fetched from another origin.

## Dependencies

Bun, Vite, Svelte 5 and SvelteKit's static adapter, at build time only. GitHub Pages to serve. The device's speech synthesis, or the committed clips. On demand: espeak-ng, to regenerate the clips.

## Failure modes

- No local voice: the clips are the mechanism, so letters are still named.
- Speech refused: the text is still written, a letter goes unnamed, and nothing waits on it.
- Storage refused or full: the built-in words still mark; the parent's words do not survive.
- An old build on a returning device: the worker moves it onto the new cache on the next load.
- Full screen is not a lock: Esc, OS shortcuts and the power key still reach the system.
